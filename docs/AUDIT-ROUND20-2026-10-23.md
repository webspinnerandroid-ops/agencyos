# Round 20 — Architecture, Security & Delivery Audit

*Principal-architect review · 2026-10-23 · scope: `agency-os` (Next.js 16.2.12, 543 src files, 151 API routes, 77 pages, 114 migrations)*

Reviewed against the live Supabase project (`axqcmiisztnqcntprhdy`, read-only schema probe), the
committed tree at `b83642a` (2026-09-15), the four house gates, and the prior audits
(`TECHNICAL_AND_SECURITY_AUDIT.md`, `DESIGN_AUDIT_AND_SUGGESTIONS.md`, `HANDOFF-AGENCY-OPS.md`).

---

## 1. Executive summary

**State: strong product, sound foundations, three shipping blockers.**

The codebase is in materially better shape than the Round 18 handoffs describe. Multi-tenant
scoping is enforced in application code with a static guard that is green; the middleware auth
model (signed cookies, CSP nonce, session refresh, workspace ownership check) is well above the
SaaS norm; the newest pipeline (Content Map → quality gate → auto-publish hold → retry ladder) is
the most carefully engineered module in the repo, with tests around the race-sensitive parts.

What stands between "works on my machine" and "safe to operate" is not architecture. It is
**drift**: code has moved ahead of the database, of the gates, and of the environment contract.

| Dimension | Verdict | Evidence |
|---|---|---|
| Architecture & consistency | **Good** | Clear layering (`app` / `components` / `lib`), documented conventions in `ARCHITECTURE.md`, no stub functions, one TODO in 543 files |
| Security (authn) | **Strong** | HMAC-signed cookies, nonce CSP, Stripe signature verification, SSRF allowlist on relay URLs |
| Security (authz) | **Weak** | 41 / 151 routes have any role check; `client` role can reach agency write endpoints |
| RLS defence-in-depth | **Absent** | 42 `auth.jwt()` policies, tenant claim never set, nothing reads policies — service-role + app-layer only |
| Data integrity | **Drift** | Migration 106 (7 tables) **not applied**; code that needs it ships |
| Billing enforcement | **Fail-open** | No `tenant_balances` row is ever provisioned, so metering is inert |
| Gates | **Amber** | 574/574 tests, build green, lint 0 errors / 715 warnings, **`tsc` red (5 errors)** |
| Test depth | **Uneven** | 58 files / 574 tests, all library-level; the money/approval path (`workflow.ts`, `ledger.ts`, `onboardClient`) is untested |
| Observability | **Missing** | No Sentry/APM/error reporting anywhere; `console.*` only |
| Ops durability | **At risk** | `infra/backup/*` (restic + restore drill) is **untracked** — exists on this machine only |

**Verdict:** no unauthenticated remote-takeover vulnerability. The exploitable class that remains is
*authenticated in-tenant cross-role* (a portal client acting as agency staff) and *authenticated
unmetered spend* (generation without a balance row). Both are cheap to close and should close before
the next feature lands.

## 3. P0 — ship blockers

### P0-1 · Migration 106 was never applied; seven tables are missing in production

Read-only probe against the live project: `activity`, `client_subsystems`, `workflow_state`,
`approval_receipts`, `email_classifications`, `email_rule_feedback`, `machine_api_keys` do not exist.
Every later migration (107–114) **is** applied, so the schema is not merely behind — it is
non-monotonic, which is worse: `supabase db push` on a fresh environment would succeed and hide the
drift.

Live code that will fail at runtime:
- Inngest: `onboardClient`, `reconcileWorkflows` (nightly 03:17), `classifyEmails` — all registered in
  [route.ts](src/app/api/inngest/route.ts#L19-L23), so the sweeps fail every night.
- Routes: `/api/agency/onboard`, `/api/agency/keys`, `/api/agency/clients`, `/api/export/seo-tool`.
- The Telegram webhook's ledger writes (`ledger.recentForClient` in the `/open` card) — silently
  swallowed, because the ledger is fire-and-forget.
- The retry ladder's doc-comment points at 106
  ([retryFailedPublishes.ts](src/lib/publishing/retryFailedPublishes.ts#L12)); its columns actually
  live in 108 (applied). Comment rot, not a defect — but it misled the last reader.

**Fix:** run `supabase/migrations/106_agency_ops_backbone.sql` in the SQL editor (idempotent), then
re-run the probe. Until then, `HANDOFF-AGENCY-OPS.md` describes a system that is not running.

### P0-2 · `client` role can drive agency write endpoints

Middleware authenticates and sets `x-user-role`, but the role is **never used to stop a request**:
`PUBLIC_ROUTES` bypasses auth, everything else needs only a valid session
([proxy.ts](src/proxy.ts#L378-L386)). Role enforcement lives in handlers, and only 41 of 151 routes
call `requireRole` / `requireClientRole`. Verified examples with **no** role check:
`POST /api/clients`, `POST /api/billing`, `DELETE /api/posts/[id]`, `DELETE /api/seo/campaigns/[id]`,
`DELETE /api/leads/[id]`, `POST /api/publish`, `POST /api/generate-content`.

`PATCH /api/posts/[id]` is tenant-scoped and has a proper approval gate
([route.ts](src/app/api/posts/[id]/route.ts#L118-L190)) — but no role check, so a portal client can
approve *and* publish the agency's content, or delete it. Tenant isolation holds; **role isolation
does not exist**.

**Fix (two lines of middleware, not 110 patches):** in `proxy.ts`, after auth resolves, block
`role === "client"` from `/api/*` and `/dashboard/*` except the portal paths and an explicit
client-safe allowlist (`/api/me`, `/api/version`, `/api/auth/*`, `/api/inbox/social/*` only if
client-facing, `/api/seo/public-*`). Then add `requireRole("agency_editor")` at the write routes in
the same pass. The middleware approach closes the whole class at once and fails closed by default.

### P0-3 · Typecheck gate is red on the current commit

`npx tsc --noEmit` fails on `makeRelay.test.ts` (lines 82, 90, 92, 93): a hand-rolled `PromiseLike`
double whose `then` is optional and a `Proxy` handler indexing with a `symbol`
([makeRelay.test.ts](src/lib/publishing/makeRelay.test.ts#L78-L96)). CI does not catch it because the
build job runs `next build` only. Either fix the double (use a real resolved promise and narrow
`typeof prop === "string"`), or add `npx tsc --noEmit` as a CI step — preferably both, because the
gate exists and is currently decorative.

## 4. P1 — fix before the next feature

**P1-1 · Token billing is switched off for every tenant without a balance row.**
`checkTokenBalance` returns `allowed: true` when `tenant_balances` has no row for the tenant
([token-billing.ts](src/lib/token-billing.ts#L44-L52), [#L86-L90](src/lib/token-billing.ts#L86-L90)).
Nothing provisions that row: registration creates tenant, role, workspace, brand profile,
subscription and license but no balance
([register/route.ts](src/app/api/register/route.ts#L108-L137)); `monthlyBillingReset` never upserts
one; the only writer is `creditAddonPurchase`. Net effect: a newly registered agency can generate
without limit until it buys something. The enforcement is otherwise well built (admin bypass is
documented and intentional) — it is simply never armed. **Fix:** insert the row at registration
(allowance from the plan), and add a backfill for existing tenants; then make a missing row
`enforced: true, remaining: 0` so failures are loud instead of free.

**P1-2 · Cookie signing has no boot-time assertion.**
`signingSecret()` silently falls back to a public constant when both `AUTH_COOKIE_SECRET` and
`ENCRYPTION_KEY` are unset ([auth-signature.ts](src/lib/auth-signature.ts#L18-L23)), and neither
variable appears in `.env.example`. Today the risk is latent (production must set `ENCRYPTION_KEY`
or encryption throws), but any environment that omits both accepts `x-user-role=super_admin` signed
with a string in this repo. **Fix:** `if (NODE_ENV === "production" && !secret) throw` at module
load, and document `AUTH_COOKIE_SECRET` in `.env.example`.

**P1-3 · `/api/auth/dev-login` is gated on env alone.** It 404s unless `ALLOW_DEV_LOGIN=true`
([dev-login/route.ts](src/app/api/auth/dev-login/route.ts#L19-L24)), and the September audit verified
it 404s on production — but the route mints a super-admin session with no credential. CI sets the
flag against the **real** Supabase project. One copied `.env` is full takeover. **Fix:** add
`process.env.NODE_ENV === "production"` to the guard; keep the CI job on a preview env.

**P1-4 · `.env.example` documents 21 of 83 variables.** Undocumented and load-bearing:
`AUTH_COOKIE_SECRET`, `GOOGLE_API_KEY`, `TELEGRAM_WEBHOOK_SECRET`, `OUTREACH_WEBHOOK_SECRET`,
`MACHINE_KEY_PEPPER`, `MAKE_RELAY_EXTRA_HOST`, `FAL_AI_API_KEY`, `ELEVENLABS_API_KEY`,
`BUNNY_*`, `SMTP_*`, `TWILIO_*`, `DISCORD_*`, `GOOGLE_CLIENT_*`, `META_APP_SECRET`, `INDEXNOW_KEY`.
Several of those default to *open* behaviour when absent (`OUTREACH_WEBHOOK_SECRET` only enforces
when set — [reply-webhook](src/app/api/outreach/reply-webhook/route.ts#L16-L20), same pattern in
`gbp/digest-reply`). `AYRSHARE_API_KEY` in the example is dead. **Fix:** regenerate the example from
`grep -rho "process.env\.[A-Z0-9_]*" src`, mark each optional vs required, and invert the webhook
secrets to fail-closed.

**P1-5 · Only 1 of 151 routes validates its body with a schema.** 93 of 94 routes calling
`request.json()` trust the shape; the `zod` + `withValidation` helper exists and is used in ~8 places.
Today the handlers destructure defensively (spot-checked `posts` PATCH — no mass assignment), so this
is a regression risk rather than a live bug. **Fix:** one route family per PR, writes first.

**P1-6 · 79 route files return `err.message` verbatim in an error path.** `internalErrorResponse()`
exists for exactly this and is adopted in 7 places
([api-http.ts](src/lib/api-http.ts#L51-L60)); `content-map` imports it and still ends with a raw
`catch → { error: message }`. PostgREST messages name columns, constraints and tables — free schema
disclosure to any authenticated caller. **Fix:** mechanical replacement, one commit.

**P1-7 · The money path has no tests.** `src/lib/agency/workflow.ts` (persist-before-wait approval
gates, single-use tokens, receipt-based idempotency), `ledger.ts`, and `onboardClient` have zero
coverage, while their tables are the ones missing from the database. Combined with P0-1, the single
most consequential subsystem in the product is both unproven and unexercised. **Fix:** apply 106,
then unit-test `decideApproval` (double-approve → one receipt), `reconcile` (stale gate → same
token), and ledger append idempotency.

**P1-8 · Disaster-recovery tooling is not in version control.** `infra/backup/{backup.sh,
restore-check.sh,RUNBOOKS.md,README.md}` and `infra/devstack/` are untracked. The restic nightly and
the monthly restore drill are the only defence beyond Supabase PITR, and they exist solely on this
disk. **Fix:** commit `infra/` (verify no secrets in `devstack/.env.example`), then wire
`restore-check.sh` into the existing CI as a scheduled job.

## 5. P2 — debt that will bite later

- **RLS is structurally dead.** 42 policies across 14 migrations key on
  `auth.jwt() ->> 'tenant_id'`; nothing ever sets that claim (`getSupabaseWithTenant`'s own comment
  admits it), and 66 files use the service-role key, which bypasses RLS entirely. The real control is
  `.eq("tenant_id", …)` plus `scripts/audit-tenant-scope.cjs` — which is green and worth keeping, but
  it is a heuristic over string chains, not a boundary. Decide: either set the claim (Supabase custom
  access-token hook or `set_config` per request) or drop the pretence from `ARCHITECTURE.md` §Security
  so the next engineer doesn't rely on it.
- **No error monitoring.** No Sentry/APM/OTel. Inngest retries and `console.error` are the whole
  story; the nightly 106 failures would be invisible. Add Sentry (server + client) or at minimum ship
  `console.error` to a log drain.
- **No route-segment error boundaries.** Only root `error.tsx` / `global-error.tsx`; a throw inside a
  dashboard page replaces the whole shell. Add `error.tsx` per dashboard hub.
- **`/dashboard/posts` is unbounded and serial.** All tenant/workspace posts, then a sequential
  per-100-id loop over `publishing_logs` (500 rows **per chunk**)
  ([page.tsx](src/app/dashboard/posts/page.tsx#L37-L70)). This is the 3.2s measured in September.
  Add pagination (or a `limit` + "load more") and one logs query with a single limit.
- **`/api/posts` still projects into the JSONB blob** (`content->title`, `content->type`,
  [route.ts](src/app/api/posts/route.ts#L27-L30)) — the exact detoast cost the Posts page's comment
  warns against. Real `title` / `type` columns exist; use them. Calendar cold-load has improved from
  44s, but this is the remaining tax.
- **Build traces the whole project.** `next.config.ts → seo/competitor-fetch.ts` does `fs` work at
  module scope, so the NFT list traces the repository (build warning). Guard with
  `/*turbopackIgnore: true*/` or move the `fs` call behind a function.
- **Stale signed cookies.** `x-client-id` is written only when `clientId` is truthy and never deleted
  when a user moves off the client role; it can outlive the role for up to 24h. Cheap: delete when
  absent, as `workspace_id` already does.
- **In-process processors double up on a multi-worker future.** `instrumentation.ts` starts the hold
  and retry intervals in-process while Inngest crons drive the same seams; claims make it safe, but
  the design assumes one Node process. Note it in the runbook.
- **Repo hygiene.** 715 lint warnings (mostly `no-explicit-any`); root-level deploy scripts/logs are
  git-ignored but clutter the tree; `supabase/pending-manual-100-101.sql` and `-102.sql` are stale
  (100–102 are applied) and should be deleted; `deploy-run.err`, `mock-wp.pid`, `test-results/` should
  not be left untracked indefinitely.
- **`posts.content_jsonb`** (migration 004) does not exist in the schema — superseded, but the
  migration stays as a trap for a fresh `db push`.

## 6. What is genuinely working (don't refactor it)

- **Cookie auth model**: HMAC-signed `x-*` values, `timingSafeEqual`, HttpOnly on authorization
  cookies, per-request CSP nonce with `script-src` free of `unsafe-inline`, foreign-project cookie
  sweep, chunked session rewrite matching `@supabase/ssr` exactly. This is better than most
  production SaaS.
- **Workspace ownership check** in the middleware (stale `workspace_id` cannot scope writes into
  another tenant's workspace) — closes the class of incident that produced the wrong-workspace import.
- **Content Map pipeline**: multipart guards via `safeFormData`, claim-before-work batch planning,
  score gate with a retry loop, 15-minute auto-publish hold with a cancel action, retry ladder
  `5m → 30m → 2h` with escalation, all idempotent by construction. The race probe (5 parallel batch
  calls, one winner) passed.
- **Make relay**: encrypted URL at rest (GCM), per-client override resolution, HTTPS + host allowlist
  enforced on **write and on delivery** — correct SSRF posture.
- **Stripe**: raw-body `constructEvent`, event-id idempotency for the ledger, `invoice.paid`
  replay-safe. Fail-closed on missing signature.
- **Tenant-scope guard** in CI-adjacent tooling, with a reviewed allowlist instead of blanket
  suppression.
