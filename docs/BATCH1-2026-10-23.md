## 2. Client-role gate in middleware — shipped

`src/proxy.ts` now fails closed for `role = 'client'`: only `/portal/**` and an
explicit allowlist (`CLIENT_PORTAL_API`) are reachable. Everything else under
`/api` answers `403 { code: "client_role_blocked" }`, and pages redirect to
`/portal/dashboard`. Allowlisted: `/api/me`, `/api/version`,
`/api/notifications*`, `/api/push*`, session/2FA self-service
(`/api/auth/set-session`, `/api/auth/resend-confirmation`, `/api/auth/2fa/*`),
`GET /api/seo/client-proposals`, `POST /api/seo/campaigns/:id/approve`.

This closes the class, not an instance: 110 of 151 routes never call
`requireRole()`, and every route added later inherits the gate.

Proven by `tests/e2e/client-role-gate.spec.ts` — a real client session over HTTP:
portal admitted, `/dashboard/clients` redirected, `/api/clients` and
`/api/posts` 403, `PATCH`/`DELETE` on a post 403 with the row unchanged,
`/api/me` and `/api/notifications` still 200, and an agency session still gets
200 on `/api/clients` (positive control against an over-broad allowlist).

## 4. Token balances provisioned — shipped

`tenant_balances` is now created for every tenant:

- **At registration** — `src/app/api/register/route.ts` calls
  `ensureTenantBalance()` after the subscription row, best-effort so a billing
  hiccup cannot fail a signup.
- **On first generation** — `checkTokenBalance()` self-heals a missing row
  (tenants that predate provisioning).
- **Backfilled** — `scripts/backfill-tenant-balances.mjs` (dry-run by default)
  inserted 8 rows; all 10 tenants now have a balance, verified.

Allowance is copied from `token_plans` by the tenant's subscription plan.

## 5. Fail closed when the balance is unreadable — shipped

`checkTokenBalance()` previously answered `allowed: true` whenever it could not
read a balance — i.e. an outage or a missing table turned the paywall off.

Now: `TOKEN_ENFORCE_BILLING=true` is the switch. Usage is metered regardless.
With enforcement on, an exhausted balance returns 402, and an unreadable /
unprovisionable balance returns 402 with "Billing is unavailable for this
workspace" instead of silently allowing spend. Super admins and agency admins
are never gated.

**Enforcement is OFF by default on purpose:** `token_plans` is empty, so every
tenant's allowance is currently $0. Flip the switch only after allowances are
configured in Admin → Token Billing, or every tenant is locked out on the next
generation.

Covered by `src/lib/token-billing.test.ts` (13 tests): provisioning is
idempotent, a plan-less tenant gets $0, remaining = unused allowance + add-on,
no negative balance, gate off = never blocked, gate on = blocked at zero,
allowed at $0.01, **fails closed** when the row cannot be written, operators
exempt.
