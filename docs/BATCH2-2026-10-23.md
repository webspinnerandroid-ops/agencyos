# Batch 2 — user-visible defects (2026-10-23)

Four defects from the SaaS QA pass, all previously pinned as failing tests. Every
pin is now a passing assertion: nothing was marked "fixed" on inspection alone.

## 1. Calendar chips were blank

`GET /api/posts` had been slimmed to project `content->title` (and friends) to
avoid shipping blog bodies on an 8-second poll. PostgREST returns those as
**top-level keys**, so every consumer's `post.content` was `undefined` and
`excerptFromContent(undefined)` fell through to `"No content"` — each chip
rendered only its status pill.

`src/app/api/posts/route.ts` now selects the denormalized `title`/`type` columns
plus `content->caption` and `content->aeoGeo` (same cost — no body is read) and
**re-shapes the response back into a `content` object**. The wire contract the UI
was written against is restored, and the payload stays small.

## 2. Post dialog said "No content" and never fetched the body

Same root cause, second symptom: the lazy-load gate asked for
`content.type === "blog" && typeof content.body !== "string"`, which could never
be true with no `content` object, so `/api/posts/[id]` was never called and the
modal stayed on "No content" even though the detail endpoint returns the full
body.

With the response shape restored, the gate works and the body hydrates. The
dialog also now renders the post's title: its heading is a generic "Post Detail",
so once content rendered there was nothing on screen saying *which* post was
open.

## 3. Scheduling drifted an hour across DST

`PublishButton` sent `new Date().getTimezoneOffset()` — the browser's offset
**today** — to `/api/publish` alongside the naive `datetime-local` value. A
December slot scheduled from a summer session was stored at 08:00 local instead
of 09:00 (and the reverse in winter).

New `offsetMinutesForLocalDateTime()` in `src/lib/scheduling.ts` returns the
offset in force **on the picked date** (constructing a local `Date` for that wall
clock is what asks the runtime for the right DST rule), and `PublishButton` calls
it. Unparseable input falls back to today's offset, matching the previous
behaviour rather than throwing.

## 4. Mobile drawer had no dialog semantics

`MobileNav`'s drawer was a bare `div.fixed`. Now:

- `role="dialog"`, `aria-modal="true"`, `aria-labelledby` pointing at the
  "Menu" heading; the trigger advertises `aria-haspopup="dialog"`.
- Focus moves into the panel on open, `Tab`/`Shift+Tab` cycle **inside** it, and
  focus returns to the trigger on close (Escape, backdrop click, or a nav link).
- Escape handling stays; body scroll lock is unchanged.
