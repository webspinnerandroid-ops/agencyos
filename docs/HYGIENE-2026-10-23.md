# Repo hygiene — root cleanup (2026-10-23)

The repository root had accumulated 183 files: 80 one-off deploy/diag/verify
scripts, 77 build and deploy logs from the August VPS rounds, nine handoff
documents, and a corrupt `package-lock` backup. None of it is imported by the app
or referenced by `package.json`; most of it was already git-ignored, which is
exactly why it never got cleaned up — invisible to `git status`, visible to
everyone opening the folder.

The root is now 15 files, all of them real config or entry-point docs:

```
AGENTS.md  ARCHITECTURE.md  CLAUDE.md  README.md
components.json  eslint.config.mjs  next.config.ts  package.json
package-lock.json  playwright.config.ts  postcss.config.mjs  tsconfig.json
vitest.config.ts  next-env.d.ts  tsconfig.tsbuildinfo
```

## Where things went

| `deploy-*.cjs/.bat/.cmd`, `verify-*.cjs`, `diag-*`, `fix-*`, `round*` helpers, `build-*.cjs`, `next-dev-run.sh` | 81 | `scripts/legacy/` | no — ignored |
| `build-out*.txt`, `round*-out.txt`, `*-out.txt`, `phase0-*.log`, `dev-server*.log`, `deploy-run.log/.err`, `package-lock.json.bak-corrupt` | 77 | `docs/archive/run-logs/` | no — ignored |

`.gitignore` now also covers `/scripts/legacy/`, `/docs/archive/`, `/*.err`,
`/*.sh` and `scripts/*.pid`, so a future stray `.err` or `.pid` cannot reappear in
`git status`.

## Why the legacy scripts are archived rather than deleted

They are a record of how the August VPS deploys were done, and deleting
untracked files is unrecoverable. But **five of them contain credentials**
(SSH/VPS passwords) in plain text. They are now inside an ignored directory:

- never commit `scripts/legacy/`;
- if those hosts are still reachable, rotate the credentials and delete the
  directory — an ignored file is still a plaintext secret on disk;
- nothing in the app, the build, or CI reads them (`package.json` references
  none of them).

- `supabase/pending-manual-*.sql` are stale but outside the root; they are
